# `.ixd.toml` Configuration Reference

**Introduced:** v0.9.0
**Purpose:** Scope what the daemon watches and what both the daemon and CLI index.

## Discovery

Both the CLI (`ix --build`) and the daemon (`ixd`) load `.ixd.toml` at startup.

The daemon looks for `.ixd.toml` files at startup:

1. At the watch root (e.g., `/home/ubuntu/.ixd.toml`)
2. One level deep in subdirectories (e.g., `/home/ubuntu/project-a/.ixd.toml`)

Multiple files are merged: root-level config applies globally; subdirectory
configs add `watch_roots` and `exclude_patterns`. The root-level `debounce_ms`
takes precedence — subdirectory `debounce_ms` values are ignored to avoid
conflicting timer strategies within a single daemon instance. Run separate
`ixd` instances if you need different debounce intervals per watched subtree.

## Schema

```toml
# .ixd.toml

# Directories within the watch root to index (optional).
# When empty, the daemon indexes the entire root recursively.
watch_roots = [
    "src",
    "tests",
]

# Directory names to exclude from indexing.
# Defaults shown below — add or override as needed.
exclude_patterns = [
    ".codegraph",
    ".git",
    "node_modules",
    "target",
]

# Debounce interval in milliseconds for file-watch event batching (optional).
# Minimum 50 ms, maximum 10 000 ms. Omit or set to null for the default.
debounce_ms = 500
```

> **Note (v0.14+):** Configurations using legacy nested tables (e.g. `[watch] paths = [...]`, `[build] exclude_patterns = [...]`) are automatically normalized into canonical flat keys with a warning.

## Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `watch_roots` | `[String]` | `[]` | Subdirectories to scope indexing to. Empty = entire root. |
| `exclude_patterns` | `[String]` | `.codegraph`, `.git`, `node_modules`, `target` | Directory names skipped during file walk. |
| `debounce_ms` | `u64` or `null` | `null` (500 ms) | File-watch batching window in ms. Range: 50–10 000. Clamped to range. |

## How Exclusions Work

Both `ix --build` and the daemon `ixd` apply exclusions through a single admission function (`builder::is_path_admitted`, `src/lib/builder.rs:152`). The policy has four layers checked in order:

1. **`watch_roots`** — if non-empty, a file or directory whose path does not start with (and is not a parent of) any watch root is excluded immediately. This is the outermost scope gate.
2. **Hardcoded directory names** — `lost+found`, `.git`, `.ix`, and `.codegraph` are always excluded as directories. These are built into `is_path_admitted` and cannot be overridden by config.
3. **`exclude_patterns`** — exact directory-name match (NOT glob). Each entry is compared against the last path component. Patterns from `.ixd.toml` are merged with the hardcoded set.
4. **Binary extensions** — files with extensions `.so`, `.o`, `.dylib`, `.a`, `.dll`, `.exe`, `.pyc`, `.jpg`, `.png`, `.gif`, `.mp4`, `.mp3`, `.pdf`, `.zip`, `.7z`, `.rar`, `.sqlite`, `.db`, `.bin`, and names ending in `.tar.gz` are excluded.

**No `.ixd.toml` fallback:** When no `.ixd.toml` exists, `Config::default` (`src/lib/config.rs:73`) supplies `exclude_patterns = [".codegraph", ".git", "node_modules", "target"]` and empty `watch_roots`. The same four-layer policy applies.

**Full and incremental indexing share one policy:** Whether the call is `ix --build` (full), `Builder::update` (daemon delta update), or `Watcher::collect_paths` (file-watch event), all route through `is_path_admitted` (`src/lib/builder.rs:152`, `src/lib/watcher.rs:214`). Changed files that fail admission are silently skipped — they are not indexed and not tombstoned.

**`.ixignore` is an event-time hedge:** The `Scanner` walker (`src/lib/scanner.rs:90`) adds `.ixignore` as a custom ignore filename via the `ignore` crate. This operates at walk time, separate from `is_path_admission`. `.ixignore` rules are honored in any directory (git or not), but they do not affect the daemon's incremental update path — only the initial full walk.

**Scanner uses a separate built-in set:** The `Scanner` filter (`src/lib/scanner.rs:95-108`) has its own hardcoded directory list (`lost+found`, `.git`, `node_modules`, `target`, `__pycache__`, `.tox`, `.venv`, `venv`, `.ix`) that differs from `is_path_admitted`. The Scanner also enforces `.git_ignore(true)` and `require_git(true)` (ancestor `.gitignore` files are never applied — audit D4).

## Examples

**Scope to specific directories:**
```toml
watch_roots = ["src", "lib", "include"]
```

Only `src/`, `lib/`, and `include/` will be indexed. All other directories
under the watch root are ignored.

**Add custom exclusions:**
```toml
exclude_patterns = [".git", "node_modules", "target", "vendor", "build"]
```

The `vendor/` and `build/` directories are custom additions beyond the
defaults (`.codegraph`, `.git`, `node_modules`, `target`). Hardcoded
dirs (`lost+found`, `.git`, `.ix`, `.codegraph`) in `is_path_admission`
(`src/lib/builder.rs:188-191`) cannot be removed. `exclude_patterns`
are exact directory-name matches, not globs.

**Tune debounce for faster or quieter change pickup:**
```toml
# Faster: 100ms debounce — changes become searchable ~100ms after save.
# Use when working interactively in an editor and want instant feedback.
debounce_ms = 100

# Slower: 2000ms debounce — fewer rebuilds during bulk operations.
# Use in CI or during mass refactors (e.g., `sed -i` across many files).
debounce_ms = 2000
```

The debounce window starts when the **first** file-change event arrives and
resets every time a **new** event arrives within the window. Only after the
window closes with no further events does the daemon batch and index the
accumulated changes. Lower values give faster searchability; higher values
reduce rebuild churn during bursty writes.

**Per-project scoping with multi-root daemon:**
```bash
# /home/ubuntu/.ixd.toml — global excludes only
# /home/ubuntu/project-a/.ixd.toml — watch src/ and lib/
# /home/ubuntu/project-b/.ixd.toml — watch app/ only

ixd /home/ubuntu
```

The daemon discovers all three config files. Project A indexes only its
`src/` and `lib/`. Project B indexes only its `app/`. Global excludes
apply everywhere.

## CLI Usage

The CLI reads `.ixd.toml` for `exclude_patterns` when building an index (`--build`):

```bash
# Build respects .ixd.toml exclude_patterns
ix --build /path/to/repo
```

`debounce_ms` only affects the daemon (`ixd` or `ix --daemon`); it is ignored
by one-shot `ix --build` and search commands.

## Verification

```bash
# Start daemon with verbose output to see config loading
ixd /path/to/root 2>&1 | grep "loaded config"

# Expected:
# ixd [project-name]: loaded config — 1 exclude patterns, 2 watch roots
```

To confirm debounce is active, check the daemon log for the watcher
initialization line or test with a short debounce value and watch for
near-instant index updates after saving a file.
